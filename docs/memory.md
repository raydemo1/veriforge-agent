# 长期记忆

长期记忆让 Agent 在不同会话之间记住你的偏好和项目知识。它的设计目标是：只记有证据的内容，过时的内容会被标记而不是被当作事实，检索失败时明确说明而不是假装「没有记忆」。

## 存储

- 唯一的数据源是 SQLite 数据库 `~/.veriforge/memory-v3/memory.db`（可用 `VERIFORGE_MEMORY_ROOT` 指定其他目录）。
- 每条记忆有稳定 ID 和版本号，所有修改都保留修订历史。
- `views/` 目录下的 Markdown 是按主题生成的只读视图，直接编辑它们不会写回数据库。
- 设置 `HARNESS_MEMORY_DISABLED=1` 完全关闭记忆；`HARNESS_MEMORY_GENERATION_DISABLED=1` 只关闭自动提取。

## 数据模型

记忆按三个相互独立的维度组织：

| 维度 | 取值 | 含义 |
| --- | --- | --- |
| `scope` | `user` / `project` | 个人跨项目偏好，或某个仓库的知识。同一仓库的多个 Worktree 共享项目记忆 |
| `topic` | 自由命名，可登记别名 | 把同一知识领域的记忆聚在一起，别名会复用已有主题 |
| `kind` | 偏好、项目事实、规范、决定、经验、工作流程 | 一条记忆的性质；同一主题下可以有不同 `kind` |

个人空间只保存来自用户本人的跨项目偏好，不接受依赖项目文件或验证结果的内容。

## 启动时加载

新会话开始时加载一份启动快照，有固定的 token 预算：

| 部分 | 上限 |
| --- | --- |
| 个人默认偏好 | 300 token |
| 项目约定 | 500 token |
| 导航说明和主题目录 | 400 token |

- 正文只包含有效且无条件适用的偏好和规范。带条件的规则、项目事实、决定、经验和流程只给出主题入口。
- 同一事实键上，项目约定覆盖个人默认（不改写原记录）。
- 过期、待确认和挂起的内容不会作为确定事实展示。
- 主题目录未展示完时，给出可以直接传给 `memory_read` 的续读参数。

启动快照在 Agent 重建和压缩后复用，回撤或恢复会话时只在新的上下文边界刷新一次。之后不会每轮自动检索或注入记忆，由模型在需要时主动调用工具。

## 工具

| 工具 | 作用 |
| --- | --- |
| `memory_search` | 搜索记忆，支持分页、路径和类别筛选。同时搜索项目和个人记忆时共用一次查询向量 |
| `memory_read` | 按范围和主题展开，或读取单条记忆及其修订历史 |
| `memory_write` | 显式保存或纠正记忆。必须逐字引用当前用户输入作为证据；纠正时传原 ID 和版本，旧修订保留 |
| `memory_validate` | 用新的用户原话确认一条记忆，并刷新文件证据 |
| `memory_forget` | 永久遗忘一条记忆，只在用户明确要求时使用，同样需要引用原话 |

## 检索

检索由两路独立召回再合并排序：

- SQLite FTS5 全文检索；
- 向量检索：硅基流动 `BAAI/bge-m3`（1024 维），需要在 `.env` 中设置 `SILICONFLOW_API_KEY`。

查询不额外调用聊天模型，但会产生 embedding 请求；同一会话内重复的查询会被缓存。语义服务失败或索引尚未完整时，结果会明确标记，不会把检索失败解释为「没有相关记忆」。

## 自动提取与整理

除了显式保存，运行时还会在后台从对话中提取记忆：

1. **提取**：每个成功的主回合结束后，安排一次后台增量提取。只读取单独记录的原始用户输入和原生结构化验证结果，不读取模型推断或任意工具输出。前台回答不等待提取完成。
2. **整理**：按事实身份和全文索引寻找已有记录，对当前有效视图做逻辑更新。历史事件不会反复成为当前事实，无法判定的冲突只返回不确定提示。
3. **索引**：向量在整理之后异步更新，失败独立重试，不会阻塞事实生效；事实更新时旧向量立即失效。

这三个阶段分别持久化：

- 连续回合会合并尚未处理的范围；新回合执行期间，相关会话的提取和整理暂停；
- 关闭进程或会话不等待后台任务，未完成的工作在下次启动时恢复；
- 文件证据变化会让相关事实过期；较旧的后台结果不能覆盖较新的已确认状态。

`/memory generate off` 关闭当前会话的自动生成，取消尚未完成的任务，并撤销这些候选对旧事实的挂起；重新打开后恢复。关闭期间的输入不会补做提取。这个开关不影响显式保存、确认和遗忘。

## 管理命令

```text
/memory status                       查看状态
/memory search <query>               搜索
/memory topics [scope]               列出主题
/memory show <id>                    查看一条记忆
/memory history <id>                 查看修订历史
/memory edit <id> <version> <body>   修改
/memory validate <id> <version>      确认仍然有效
/memory restore <id> <revision> <version>   恢复到某个修订
/memory forget <id> <version>        遗忘
/memory retry                        重试失败的后台任务
/memory use on|off                   当前会话是否使用记忆
/memory generate on|off              当前会话是否自动生成记忆
```

ID 可以带 `project:` 或 `user:` 前缀。

遗忘会删除记忆及其修订，并阻止旧来源再次被提取；原始会话日志保留。之后如果你明确要求重新记住，`memory_write(restore_forgotten=true)` 会用新证据重新保存。

## 验证脚本

- `eval/scripts/check_memory_consolidation.py`、`eval/scripts/check_memory_runtime.py`：离线检查整理和运行时行为；
- 真实模型评测必须显式加 `--run`，场景和请求上限写入每次评测的产物，不属于默认测试集。

历史验收记录见 [eval/reports/](../eval/reports/)。
