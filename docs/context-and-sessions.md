# 上下文与会话

本文说明对话上下文如何保存、压缩和恢复，以及多会话、回撤和 Worktree 的工作方式。

## 会话日志与上下文版本

每个会话有一份只追加的 JSONL 日志（`SessionJournal`），保存原始消息、用户输入、验证结果和上下文版本。日志是唯一的事实来源：只有成功写入日志后，内存中的活动视图才会更新。

模型实际看到的消息列表由 **Context Epoch**（上下文版本）描述：

- `ContextHistory` 冻结已提交的消息，读取时得到的是独立快照；
- 普通的用户消息和工具结果只是追加到当前 Epoch；
- Agent 重建、请求契约变化、上下文压缩和回撤会建立新的 Epoch，并把基础视图写入日志。

恢复会话时，从最近一个 Epoch 的基础视图开始，再追加它之后的消息，就得到与中断前一致的上下文。子 Agent 使用各自的日志，它们的 Epoch 不会覆盖主 Agent 的恢复视图。

## Token 预算

- 上下文窗口由 `HARNESS_CONTEXT_WINDOW_TOKENS` 设置（默认 200000）。
- 达到窗口的 80%（`COMPRESS_THRESHOLD`）时自动压缩，同时为模型输出预留空间。
- 估算会计入 reasoning 内容和工具定义，但它是本地估算，不等于服务端的精确计数。
- 每轮的 token 和工具调用次数分别受 `MAX_AGENT_TOTAL_TOKENS`、`MAX_AGENT_TOOL_CALLS` 限制；达到 `AGENT_BUDGET_WARN_FRACTION`（默认 80%）时，向对话追加一次运行时提醒。

预算提醒和其他运行时事件只在待执行的工具全部返回之后追加，避免打断工具调用与结果的配对。

## 压缩

压缩可以手动触发（`/compact`），也会在达到阈值时自动进行。它的行为：

- 把本轮之前较早的完整交互替换为摘要，保留最近的完整工具组及其原始 reasoning；
- 摘要分为「历史工作」和「当前运行时事实」两部分；
- 中间件可以在压缩后重新注入动态上下文（例如启动时的记忆快照）；
- 摘要失败、工具调用配对不完整或没有节省空间时不提交；
- 压缩只改变当前上下文视图，原始消息仍完整保存在日志中。

## Provider 差异

- DeepSeek 的 `reasoning_content` 在流式、非流式和跨轮次请求中都会保留并回传。
- 其他 provider 的出站请求会去掉它们不支持的字段，内存中的消息不受影响。
- 只有 OpenAI 原生接口支持 `prompt_cache_key`；GPT-5.6 及以后的模型还会在 system 消息上设置显式缓存断点。

## 请求诊断

每次模型请求都会在传输层记录：实际的 provider 和模型、重试次数、Epoch、工具顺序指纹、消息字段指纹和长度、与上一次请求的最长公共消息前缀及首个差异位置，以及返回的用量和延迟。

诊断不记录完整的 Prompt、reasoning 或附件内容。服务端没有返回缓存用量时记为「未知」，而不是零命中。这些本地指纹可以帮助定位「为什么缓存没命中」，但不能证明服务端一定命中了缓存。

## 运行状态查询

`get_runtime_status(section)` 工具让模型读取已有的运行状态：`task`、`budget`、`verification`、`environment` 或 `agents`。它不会运行测试，也不会创建新的状态缓存。验证结果绑定文件指纹，文件之后被修改，对应的结论就会标记为过期。

## 回合结束后的验证

模型循环结束后，运行时同步检查本轮改动过的文件：

| 语言 | 自动执行 | 标记为「已跳过」并给出命令 |
| --- | --- | --- |
| Python | AST 语法检查、Ruff（若已安装） | — |
| TypeScript | 最近的 `tsconfig.json` 对应的 `tsc --noEmit` | ESLint（会加载项目插件） |
| Go | `gofmt -d` | `go test`（会执行测试代码） |
| Rust | — | `cargo check`（可能运行构建脚本和过程宏） |

会执行项目代码的检查不会自动运行，需要时由 Agent 通过 `bash` 在会话权限下执行。检查前后比对源码指纹和工作区变更序号，期间文件发生变化时，结果标记为过期。检查范围只限本轮实际改动的文件，没有 Git 的目录也能识别 Shell 造成的修改。依赖、缓存、构建目录以及 `.harbor`、`.harness`、`.veriforge` 中的运行产物不参与检查。

## 多会话

一个工作台可以同时打开多个会话。每个会话独立保存对话、消息队列、审批、模型设置、草稿和后台任务。

- **按需初始化**：会话第一次执行时才创建运行时，切换标签只读取已保存的界面和历史。
- **空闲休眠**：连续空闲两分钟后释放运行时，下次执行时自动恢复，会话 ID、消息和界面状态不变。排队消息、待处理审批、运行中的后台进程或子 Agent、未退出的工具、未应用的改动提案和待解决冲突都会阻止休眠。
- **共享额度**：同一项目的会话共享模型并发额度（默认 3）、工具线程和网络 / MCP 连接额度。等待额度时可以正常取消。
- **停止与关闭**：输入区的「停止」只取消当前回合，保留排队消息和后台任务；Ctrl+C 或关闭工作台会清理所有会话及其进程。关闭标签只是隐藏会话，恢复后沿用原 ID。
- **分支**：`/fork` 从最近一个完整、稳定的历史边界创建新会话。

界面顶部的「资源」面板显示正在运行的会话、等待原因、后台进程的内存和 CPU 时间以及最近的失败。

## 共享工作区与冲突

默认所有会话共享同一个工作目录（Local）：

- 不同文件可以并行修改；
- 写入同一文件前校验版本。发生真实冲突时，Agent 最多自动协调两轮；三方合并能安全通过时自动应用，仍有重叠或无法验证时展示最终差异，确认后才覆盖 Local；
- 短时的未知命令执行期间互斥写入；长期运行的后台 Shell 不阻塞其他会话写入，但它直接改文件时可能产生冲突；
- 范围未知的操作不会扫描整个项目，只记录一个「无法完整回撤」的边界，之后回撤跨过这个边界时会警告并拒绝。

## 隔离工作区（Worktree）

需要隔离时，选择「隔离工作区」会 Fork 一个新会话，在新的 Git Worktree 中工作，原会话和任务保留不变。

- Worktree 继承当前 Local 的未提交改动和未被忽略的未跟踪文件；
- 源会话正在执行回合时不能创建，需要等回合结束或先停止；
- 暂不支持从一个 Worktree 再派生 Worktree；
- 创建失败时会清理本次新建的 Worktree 和会话，并报告错误；
- 「应用到 Local」只计算 Worktree 创建之后的改动，并检查 Local 在此期间的修改，冲突时不会直接覆盖。

## 回撤

每个稳定回合结束后都会保存回撤点。在界面中悬停或用键盘聚焦某一轮，选择「回撤到此处」即可回到该回合结束时的状态；「会话开始」可以撤回第一轮。

- 回撤沿用当前会话 ID，只撤销本会话自己做出、且仍能安全恢复的文件改动；
- 其他会话或外部程序之后又修改了同一文件，回撤会被拒绝；
- 活动对话、计划和任务状态回到目标边界，原始日志保留；
- 仍在运行的后台 Shell 不阻止回撤，但回撤时会校验文件版本并提示可能的冲突；
- 文件和会话记录通过可恢复的事务一起更新；数据库、远端请求等外部副作用不在恢复范围内。
