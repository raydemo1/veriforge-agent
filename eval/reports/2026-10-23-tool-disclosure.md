# 工具披露方式评测

日期：2026-10-23。

## 目的

比较两种向模型披露工具的方式：原生工具 Schema 追加（生产路径），以及「固定工具入口」候选方案，关注成功率、参数错误和 DeepSeek 上下文缓存命中。

## 设置

使用配置中的 `normal` 模型强度，请求模型名为 `deepseek-v4-flash-vision-exp`，thinking 开启。共 43 次模型请求，未扩展到 72 次的上限。

## 结果

| 指标 | 原生 Schema | 固定入口候选 |
| --- | ---: | ---: |
| 成功任务 | 6/6 | 6/6 |
| 参数错误 | 0 | 0 |
| 模型请求 | 21 | 22 |
| 缓存命中 Token | 140,544 | 156,160 |
| 缓存未命中 Token | 13,369 | 7,549 |
| 整体命中率 | 91.31% | 95.39% |
| 排除各任务首请求后的命中率 | 94.83% | 95.09% |
| 排除各任务首请求后的未命中 Token | 5,879 | 6,047 |
| 总 Token | 155,809 | 165,670 |
| 端到端耗时 | 27.457 秒 | 27.139 秒 |

## 分析

最初设定的「总 Token 不能增长」门槛已撤回。缓存收益应比较命中率、绝对未命中量，以及
`命中量 × 命中单价 + 未命中量 × 未命中单价 + 输出量 × 输出单价`，单价使用调用时适用的模型费率；总 Token 只作为容量指标。

这轮实验的公共前缀没有按组隔离：原生路径的第一条请求完全未命中，后续候选能够复用公共前缀。因此整体命中率的优势不能直接归因于固定入口，排除首请求也无法完全消除跨组预热的影响。

## 结论

缓存收益证据不足。保留原生工具披露方式，移除固定入口候选，不追加实验。专项评测脚本已随候选实现一并移除。

原始观测位于 `eval/results/deepseek-disclosure-20261023-063950/`（不进入 Git）。其中 `summary.json` 是按当时门槛的结果，`cache_assessment.json` 是修正后的缓存评估。
